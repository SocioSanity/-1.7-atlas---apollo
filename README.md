# Atlas

Atlas is a native C chat application and sequential model coordinator. Simple prompts go straight to inference; larger tasks can be split into subtasks, handled by one specialist at a time, combined, and checked by the coordinator. A larger reference model can review low confidence or rejected answers. Each model process exits before the next one starts, keeping model memory use sequential.

## Current limits

- The built-in inference backend derives dimensions from GGUF metadata and tensor shapes, so supported model sizes do not need compile-time constants.
- The current execution backend supports the Qwen2 tensor layout and the quantization types implemented in `src/brain_runtime.c`. It cannot currently run every GGUF architecture or every tensor type. A model with an unsupported architecture or quantization is rejected; adding it requires a C backend implementation, not just a model file.
- The coordinator requests a maximum of four specialist attempts per subproblem and at most one larger reference pass. This is a bounded search, not a guarantee that every answer is correct.
- Conversation transcripts, a persistent assistant preference profile, and coordinator verification outcomes are stored locally. Verification results adjust future specialist routing; Atlas does not perform online weight training.
- Automatic routing favors task fit and saved results, with model size used as a smaller speed tie-breaker. Models larger than 2 GB are excluded from automatic routing on this machine because the 8B model falls back to slow CPU inference when GPU allocation fails.
- Verification is generated by another language model and is not a proof of correctness.

## Run

- `atlas_1_0_chat.exe` opens the standard chat GUI.
- `atlas_compact_chat.exe` opens the compact profile.
- `atlas_chain_monitor.exe` opens the separate plain-text coordinator/specialist transcript view.
- Keep the executables beside the `model/` directory. The standard chat uses `specialist_loader.exe` and `atlas_dynamic_infer.exe` to load supported models by path.
- Put additional GGUF specialists under `model/specialists/`. Model files are not included in source releases; obtain them from their authors and follow each model's license.

## Build

Use GCC for Windows with the Direct3D 12 development libraries available, then run `make`. The dynamic inference target reads supported model dimensions at runtime. The compact and standard targets remain for compatibility with the existing profiles.

## Local data

Conversation logs and routing feedback are stored beside the application. They may contain prompts and responses. The feedback file stores model paths and counts, not model weights. Delete local memory, transcript, and learning files to clear this data.
